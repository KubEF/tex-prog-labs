Основная цель этого мастер-класса — научить вас взаимодействовать с операционной системой Linux через консольный интерфейс (Shell), уверенно навигироваться по файловой системе, управлять файлами, перенаправлять данные и устанавливать программы через пакетный менеджер.

== Раздел 1. Окружение и навигация в файловой системе

=== Теория и концепции
В Linux нет привычных для пользователей Windows дисков `C:` или `D:`.
Файловая система Linux представляет собой единое дерево, начинающееся с корневого каталога `/` (slash).

* `~` (тильда) — краткое обозначение вашей домашней директории (например, `/home/username`).
* `.` (точка) — текущая директория.
* `..` (две точки) — родительская директория (на один уровень выше).

=== Основные команды
[cols="1,3", options="header"]
|===
| Команда | Назначение
| `pwd` | Print Working Directory — показывает, где вы сейчас находитесь.
| `ls` | List — выводит содержимое каталога.
| `cd` | Change Directory — переходит в указанную папку.
|===

=== Документация и флаги
Любая утилита поставляется с документацией. Базовый способ её получить — команда `man` (manual). Быстрая справка доступна через флаг `--help` у большинства программ.

* `man <команда>` — подробное руководство по команде.
* `<команда> --help` — краткая справка с описанием всех флагов.
* Флаги меняют поведение команды: `ls -la` уже показал нам флаги `-l` (подробный список) и `-a` (скрытые файлы).

Практикуйтесь:

[source,bash]
----
man ls
ls --help
date --help
----

=== Практическое задание

1. Откройте терминал и узнайте ваше текущее местоположение:
+
[source,bash]
----
pwd
----

2. Посмотрите содержимое домашней директории, включая скрытые файлы (имена которых начинаются с точки), а также с подробной информацией (права доступа, размер, дата):
+
[source,bash]
----
ls -la ~
----

3. Создайте рабочую структуру папок для нашего курса с помощью команды `mkdir` (флаг `-p` позволяет создавать вложенные папки за один раз):
+
[source,bash]
----
mkdir -p ~/workspace/intro_linux/{data,logs,scripts}
----
+
[NOTE]
.Фигурные скобки `{...}` — brace expansion (расширение фигурных скобок)
====
Это не специальный синтаксис `mkdir` — скобки раскрывает сам shell *до* запуска команды. Список через запятую внутри `{a,b,c}` размножает шаблон: вместо одного аргумента `~/workspace/intro_linux/{data,logs,scripts}` shell подставляет три: `~/workspace/intro_linux/data`, `~/workspace/intro_linux/logs`, `~/workspace/intro_linux/scripts`. Команда, фактически выполненная shell'ом:

[source,bash]
----
mkdir -p ~/workspace/intro_linux/data ~/workspace/intro_linux/logs ~/workspace/intro_linux/scripts
----

Проверить, что именно видит команда, можно с помощью `echo`:

[source,bash]
----
echo {data,logs,scripts}
----

Вывод: `data logs scripts`.

Brace expansion поддерживает и диапазоны: `{1..5}` раскроется в `1 2 3 4 5`. Ещё удобнее комбинировать с путями: `mkdir -p {data,logs}/{raw,archive}` создаст четыре вложенные папки.
====

4. Перейдите в созданную папку `intro_linux` и убедитесь, что вы находитесь внутри:
+
[source,bash]
----
cd ~/workspace/intro_linux
pwd
----

== Раздел 2. Работа с файлами и текстовым редактором

=== Теория и концепции
Одно из главных правил Unix-подобных систем: **«Всё есть файл»**. Конфигурации программ, системные логи и даже устройства хранятся в виде файлов или представлены файловым интерфейсом.

=== Основные команды
* `touch filename` — создает пустой файл.
* `cp source destination` — копирует файл или папку (`cp -r`).
* `mv source destination` — перемещает или переименовывает файл/папку.
* `rm filename` — удаляет файл (`rm -r` удаляет папку и её содержимое).
* `cat`, `head`, `tail` — просмотр содержимого файлов.

=== Практическое задание

1. Создайте пустой файл конфигурации и откройте его в консольном текстовом редакторе `nano`:
+
[source,bash]
----
nano ~/workspace/intro_linux/config.txt
----

2. Внутри редактора `nano` введите следующие две строки:
+
[source,text]
----
APP_ENV=development
LOG_LEVEL=debug
----
+
_Для сохранения нажмите kbd:[Ctrl+O], затем kbd:[Enter]. Для выхода нажмите kbd:[Ctrl+X]._

3. Прочитайте содержимое созданного файла:
+
[source,bash]
----
cat ~/workspace/intro_linux/config.txt
----

4. Скопируйте файл конфигурации в папку `data` под новым именем, а затем переименуйте оригинал:
+
[source,bash]
----
cp config.txt data/config.backup.txt
mv config.txt app_config.txt
----

5. Посмотрите первые и последние строки любого существующего системного лога (например, лога установки пакетов `/var/log/dpkg.log`):
+
[source,bash]
----
head -n 5 /var/log/dpkg.log
tail -n 5 /var/log/dpkg.log
----

== Раздел 3. Перенаправление потоков и конвейеры (Pipes)

=== Теория и концепции
У любой команды в Linux по умолчанию есть три стандартных потока данных:

1. `stdin` (0) — стандартный ввод (клавиатура).
2. `stdout` (1) — стандартный вывод (экран).
3. `stderr` (2) — поток ошибок (экран).

Мы можем перенаправлять эти потоки в файлы или связывать утилиты между собой через конвейер (`|`).

* `>` — перенаправить `stdout` в файл (перезаписать файл).
* `>>` — дописать `stdout` в конец файла.
* `2>` — перенаправить ошибки `stderr` в файл.
* `|` (pipe) — передать `stdout` левой команды на `stdin` правой команды.

=== Практическое задание

1. Выведите список всех переменных окружения текущей сессии и сохраните их в файл `data/env_vars.txt`:
+
[source,bash]
----
env > data/env_vars.txt
----

2. Посчитайте количество строк в полученном файле с помощью утилиты `wc -l`:
+
[source,bash]
----
wc -l data/env_vars.txt
----

3. **Конвейер:** Найдите среди системных переменных переменную `PATH` и вывод передайте утилите `tr`, чтобы заменить двоеточия на переносы строк:
+
[source,bash]
----
grep "^PATH=" data/env_vars.txt | tr ':' '\n'
----

=== Переменные окружения

Переменные окружения — именованные значения, которыми shell обменивается с запускаемыми программами. Среди стандартных: `PATH` (где искать исполняемые файлы), `HOME` (домашняя директория).

У переменных три уровня видимости:

1. **Локальная** — `MY_VAR=hello`. Живёт только в текущем shell, не передаётся дочерним процессам и исчезает при закрытии терминала.
2. **Экспортированная** — `export MY_VAR` (или `export MY_VAR=hello`). Наследуется дочерними процессами, но тоже теряется при закрытии сессии.
3. **Постоянная (глобальная)** — строка `export ...` записана в файл настройки shell `~/.bashrc`. Загружается в каждой новой сессии.

Чтобы удалить переменную: `unset VAR` — из текущей сессии; если она записана в `~/.bashrc`, удалите строку оттуда и примените изменения командой `source ~/.bashrc`.

==== Практика

1. Создайте локальную переменную и проверьте её значение:
+
[source,bash]
----
MY_VAR=hello
echo $MY_VAR
env | grep MY_VAR
----
+
В выводе `env | grep` переменной не будет -- она не экспортирована.

2. Экспортируйте её и проверьте снова:
+
[source,bash]
----
export MY_VAR
env | grep MY_VAR
----

3. Сделайте переменную постоянной, добавив её в `~/.bashrc`, и проверьте в новой сессии:
+
[source,bash]
----
echo 'export GREETING=hi' >> ~/.bashrc
source ~/.bashrc
echo $GREETING
----

4. Отредактируйте стандартную переменную `PATH`, добавив свою папку:
+
[source,bash]
----
echo $PATH
export PATH=$PATH:~/bin
echo $PATH
----
+
Чтобы изменение осталось постоянным, допишите `export PATH=$PATH:~/bin` в `~/.bashrc`.

5. Удалите переменную:
+
[source,bash]
----
unset GREETING
env | grep GREETING
sed -i '/GREETING/d' ~/.bashrc
source ~/.bashrc
----

== Раздел 4. Пакетный менеджер apt и права sudo

=== Теория и концепции
В Linux программы обычно не скачиваются сайтов в виде `.exe`-файлов. Вместо этого используется **пакетный менеджер**, который скачивает и устанавливает проверенное ПО из официальных репозиториев.

В Ubuntu системным пакетным менеджером является `apt`. Для установки программ нужны права администратора (`root`), которые временно вызывают через команду `sudo`.

=== Практическое задание

1. Обновите индекс доступных пакетов в репозиториях:
+
[source,bash]
----
sudo apt update
----

2. Установите полезную консольную утилиту `tree` (строит визуальное дерево файлов и папок) и демонстрационный пакет `cowsay`:
+
[source,bash]
----
sudo apt install -y tree cowsay
----

3. Визуализируйте созданную структуру вашей рабочей директории:
+
[source,bash]
----
tree ~/workspace/intro_linux
----

4. Проверьте работу `cowsay`, передав ему текст через пайп:
+
[source,bash]
----
echo "Hello, Linux!" | cowsay
----
